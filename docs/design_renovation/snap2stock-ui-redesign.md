# Snap2Stock UI修正仕様書

作成日: 2026-10-01 / バージョン: 1.0

## 1. 目的と実装方針

中古車輸出ヤードで、車両を検索し、保管場所と管理情報を素早く確認できる画面に改善する。過剰な装飾を減らし、情報の読みやすさ、操作の一貫性、画面幅への適応を優先する。

本書はClaude Codeが既存リポジトリを修正するための仕様である。新規アプリの作り直しではない。既存のコンポーネント、データモデル、API、登録・読取・取込処理を確認してから変更する。

### 必須の前提

- **現在のロゴ画像をそのまま使用する。** 形状・色・文字・縦横比を変更しない。生成画像の文字だけのロゴへ置換しない。
- 白・薄いグレー・青を基調にする。青は既存ロゴの青系統に調和させる。
- UIの見た目、文言、配置、既存機能への導線を修正する。
- 保存データ、APIの契約、QRの内容、画像解析の方式、Excel取込形式、出荷完了処理の意味は維持する。
- 本書の文章を実装仕様の正とする。添付画像はレイアウト参考であり、画像内の追加機能や不整合をそのまま実装しない。
- 未確認の機能が必要になった場合、既存コードを調査し、機能追加として切り分ける。表示だけのダミーボタンを追加しない。

### 調査の範囲

https://snap2stock.vercel.app/ のPC画面で、ダッシュボード、在庫一覧、マップ、車両詳細、区画選択、登録フォーム、QRスキャナー、当日の出荷予定を確認した。検索による絞り込みと、一覧の区画ボタンから対象車両のマップ表示を確認した。

車両保存・削除・出荷完了、カメラ読取、画像アップロード、Excel取込の実処理、スマホ表示、内部コードは未検証。実装時にコードと実機表示を確認する。調査後に既存画面が更新されている場合は、現在の実装を起点に差分を適用する。

## 2. 対象範囲

| 区分 | 今回実装する内容 |
|---|---|
| 共通 | ロゴ維持、配色、文字、余白、角丸、ナビゲーション、アクセシビリティ、レスポンシブ対応 |
| ダッシュボード | 大きな機能カードを縮小し、既存データを使った件数と出荷情報を見やすくする |
| 在庫一覧 | 横はみ出しと過剰な改行を解消し、検索と表を整理する |
| マップ | 検索導線、区画の視認性、対象車両の情報表示を改善する |
| 詳細 | 主要情報を上部へ集約し、QRを適切な大きさにする |
| 登録 | 文言を統一し、項目を整理し、手入力と写真入力の関係を明確にする |
| QR | 既存の読取方式に合った案内と代替導線を表示する |
| 出荷予定 | 既存の当日出荷情報と操作を表形式で整理する |

### 今回の対象外

車両写真の新規保存機能、ユーザー管理、通知、複数ヤード切替、車両情報編集機能の新設、出荷履歴機能の新設、日付指定の出荷検索、ページネーションやソートの新設、バックエンドの刷新、OCR方式の変更、認証・アクセス保護設定の変更、デプロイ。

上記が既存機能として実装されている場合は利用できるが、本書を理由に新規実装しない。生成画像に存在しても機能追加の承認を意味しない。

## 3. デザイン共通仕様

### 3.1 ロゴと配色

既存ロゴのアセットをリポジトリ内で特定し、現在のロゴを継続使用する。左上の白い背景上に配置し、画像は object-fit: contain 相当で表示する。PCではロゴと名称を含めてサイドバー幅内に収める。狭い画面でもロゴを極端に小さくしない。

以下は初期トークン案。primaryだけは、既存ロゴの青を確認したうえで読みやすい色味に微調整できる。ロゴ画像自体を変更してはならない。

| トークン | 初期値 | 用途 |
|---|---|---|
| page | #F6F8FA | ページ背景 |
| surface | #FFFFFF | サイドバー、表、入力欄 |
| text | #1F2937 | 本文・見出し |
| text-muted | #596579 | 補助文・ラベル |
| border | #D8DEE7 | 境界・入力欄 |
| primary | #2563EB | 主要操作・リンク |
| primary-hover | #1D4ED8 | 主要操作のhover |
| selected-bg | #EFF6FF | 選択中の背景 |
| success | #166534 / #DCFCE7 | 完了・準備済みの文字 / 背景 |
| warning | #92400E / #FEF3C7 | 確認待ちの文字 / 背景 |
| danger | #B91C1C / #FEE2E2 | エラー・削除の文字 / 背景 |

緑は完了状態、黄〜オレンジは注意、赤はエラーや危険な操作に使用する。色だけで状態を示さず、必ず文言を併記する。実装した色の組み合わせは本文で4.5:1以上、UI境界やフォーカスなどは3:1以上を確認する。

グラデーション、紫の装飾色、発光、カードごとの多色背景、大きいドロップシャドウは使用しない。

### 3.2 文字・寸法

- 日本語対応の既存sans-serifを優先。なければ system-ui, -apple-system, "Noto Sans JP", sans-serif 相当。
- 本文14〜16px、補助文12〜14px、ページ見出し24〜28px、セクション見出し18〜20px。
- 見出しは通常体。斜体、装飾的な全大文字、過剰な字間は廃止する。
- 余白は4/8/12/16/24/32pxの段階で統一。PCの本文余白は24px程度。
- 角丸は入力・ボタン6px、セクション8pxを基本とし、極端な丸みを避ける。
- ボタン・入力欄は高さ40〜44px。スマホのタップ対象は44px以上。
- 表の行高は目安56〜72px。データの長さに応じて拡張できる。
- 基本は細い境界線で区切る。影は浮いたメニューやダイアログなどに限定する。

### 3.3 共通レイアウト

- PC: サイドバー200〜220px程度、ヘッダー56〜64px程度。残りの幅を本文に使う。
- サイドバーは白。QR画面のみ濃紺にするなど、画面ごとの変化を禁止する。
- 選択中の項目は薄い青背景と青い文字・アイコンで示す。
- ナビゲーション文言を「ダッシュボード」「在庫一覧」「ヤードマップ」「車両登録」「QRスキャン」「出荷予定」に統一する。同じ在庫機能の一覧・マップを別入口として配置してよいが、検索状態を共有する。
- Excel取込は在庫一覧の操作として配置し、ダッシュボードからも既存処理へ到達できるようにする。
- ヘッダーのヤード名は、既存の実際の値を表示する。切替が未実装ならドロップダウン風にしない。
- ユーザー名・通知・設定は既存機能がある場合のみ表示。架空のユーザー名や無反応アイコンは使わない。
- RESET SYSTEMは常設の目立つ操作から外す。既存の管理・デバッグ操作の中に移し、機能や権限の意味は変更しない。

### 3.4 文言

UIラベルと説明は日本語に統一する。ブランド名、車名、VIN、既存マスタの値は保持する。英語マスタの表示を翻訳する場合、保存値は変更しない。

| 現在の表記例 | 修正後 |
|---|---|
| Stock List / Yard Map | 在庫一覧 / ヤードマップ |
| Vehicle Registration | 車両登録 |
| QR Scanner | QRスキャン |
| DETAILS | 詳細 |
| PRINT LABEL | QRラベルを印刷 |
| DELETE ASSET | 車両を削除 |
| TECHNICAL PASSPORT | 車両情報 |
| PHOTO AUTO-FILL | 写真から入力 |
| CONFIRM AND SAVE | 登録する |
| TARGET SLOT | 保管場所 |
| DOCS: OK | 書類：準備済み |
| DOCS: PENDING | 書類：確認待ち |
| DOCS: MISSING | 書類：不足 |

OK / Pending / Missing の意味は既存実装で確認し、意味が異なる場合は正しい表示ラベルへ調整する。「Status Insight」の長い文章は、同じ情報を構造化して表示できる場合に重複を省く。

## 4. 画面別仕様

### 4.1 ダッシュボード

大きい4色の機能カードを廃止し、業務情報と短い操作導線へ置き換える。

1. ページ見出し。
2. 車両検索欄と「車両を登録」。検索は既存の検索処理を再利用し、結果がある在庫一覧へつなぐ。
3. 小さい件数表示「在庫」「本日出荷」。書類未完了件数は既存ステータスから正しく計算できる場合のみ表示。
4. 本日の出荷車両をコンパクトな表で表示し、詳細・保管場所へつなぐ。
5. 「在庫一覧」「QRスキャン」「Excel取込」の短い導線。

「要確認」一覧は既存の書類ステータスから表示可能な場合に追加してよい。画像にある写真・新たな警告判定は必須ではない。0台でも情報の意味が分かる文言を表示する。

参考画像: ![ダッシュボード案](images/01-dashboard.png)

### 4.2 在庫一覧【最優先】

- 上部に見出し、検索結果件数、「Excel取込」「車両を登録」を配置する。
- 検索欄のラベルまたは補助表示は「車体番号・車名・ナンバーで検索」。placeholderだけをアクセシブルな名前にしない。
- 会社・メーカーの既存検索条件を維持し、用途が分かるラベルを付ける。マスタ選択が既存で用意されていなければ、画像に合わせるためだけに自由入力をselectへ変えない。
- 書類フィルタは既存機能がある場合のみ表示。
- 検索条件をまとめて消す「条件をクリア」を用意する。
- 一覧 / マップ切替を検索欄付近に配置し、条件と選択車両を可能な範囲で保持する。
- 主な列: 車両、車体番号・ナンバー、保管場所、書類、操作。会社・出荷予定は幅に余裕がある場合に表示する。
- 車体番号と区画番号を単語途中で折り返さない。区画は「A-4」の形式で一行表示する。
- 詳細は行クリックまたは明示したボタンから開く。区画リンク・メニューのクリックが行クリックと競合しないようにする。
- 削除は行内の目立つアイコンからメニュー内へ移す。QR操作はラベルやツールチップを付ける。
- PC 1280px幅で、主要列と操作が隠れないこと。狭い画面で全列を無理に収めず、優先列の絞り込みかモバイル表示へ切り替える。
- 写真は既存データに画像がある場合のみ使用。写真なしでも車名・年式・色で識別できる。架空の車両写真は実装に含めない。

参考画像: ![在庫一覧案](images/02-inventory.png)

### 4.3 ヤードマップ【最優先】

- マップ画面にも検索欄を常時表示する。「検索窓から選択」という案内と実際のUIを一致させる。
- 検索結果が複数の場合は選択できる候補を表示。1件に絞られた場合も、どの車両を選択しているか明示する。
- 区画リンクから開いたときは対象区画を強調し、車両情報を同時に表示する。
- マップ背景は明るい色。空き・使用中・選択中を文字と色・境界で区別する。
- 列A〜J、行1〜10という既存配置を維持する。新しい座標の割当てや保管場所の意味を変更しない。
- 車名と車体番号末尾など短い識別情報を使用中セルに表示できるようにする。
- 検索対象以外の使用中区画も表示し、絞り込みにより空き区画に見える誤解を防ぐ。車両の候補絞り込みと実際の占有表示を分ける。
- PCはマップ＋右側の車両情報。情報は保管場所、車名、車体番号、会社、書類状況、「詳細」。
- 未選択時は「区画または検索結果から車両を選択してください」。検索結果0件は別の状態として表示する。
- 区画ボタンに「A-4、Toyota Prius、使用中」などの名前を付ける。キーボードで選択できる。

参考画像: ![ヤードマップ案](images/03-yard-map.png)

### 4.4 車両詳細

- 上部に戻る導線と車名。続いて車体番号・保管場所・書類状況・出荷予定日を配置。
- 保管場所の近くに「マップで確認」。既存の対象区画表示を再利用する。
- 本文は「基本情報」「管理・出荷情報」「メモ」に整理。現在表示されているデータ項目を失わない。
- 値ごとの巨大なカードを廃止し、ラベルと値を整列させる。
- QRはPCで120〜160px程度を初期目安とし、必要な可読性を確保する。装飾的な傾きをなくし、QR周辺の白い余白を保持する。
- QRラベル印刷は既存処理を維持。縮小した画面表示が印刷用サイズに影響しないようにする。
- 削除はメニュー内へ移す。既存の確認フローを維持する。
- 画像内の「情報を編集」は既存編集機能がある場合のみ表示する。

参考画像: ![車両詳細案](images/04-vehicle-detail.png)

### 4.5 車両登録

- 既存の区画選択マップを維持し、選択後はフォームへ直接進む。単なる空き区画選択の確認ダイアログは省略する。ただし既存処理が占有状態や競合を確認する場合、その検証は省略しない。
- 「YES, START PHOTO SCAN」のような手入力と矛盾する文言をなくす。
- ページ名は「車両登録」。既存選択済みの保管場所を上部に一度表示する。
- 「写真から入力」を補助操作として配置。手入力は常に行える。
- 項目を「基本情報」「管理・出荷情報」に分ける。
- 基本情報: メーカー、車名、車体番号、ナンバー、年式、色。
- 管理・出荷情報: 保管場所、入庫日、会社、輸出先、書類状況、出荷予定日。保管場所は上部とフォームで重複させない。
- 必須項目は現在のバリデーションに従い、ラベルに「必須」を表示する。画像のアスタリスクを根拠に必須条件を変更しない。
- 日付の表示は可能な箇所で YYYY/MM/DD。保存形式とタイムゾーン処理は維持する。ネイティブ入力の表示はブラウザ依存として扱う。
- 入力エラーは該当欄の近くに説明。既存の送信中状態を分かりやすく表示し、重複送信を防ぐ。
- 写真解析後は読み取られた値を確認・修正できる既存フローを維持する。結果を未確認のまま自動保存しない。
- 下部に「キャンセル」「登録する」。小さい画面でも到達できるようにする。

参考画像: ![車両登録案](images/05-registration.png)

### 4.6 QRスキャン

- 主要見出しと短い説明を表示し、大きい装飾カードとアイコンを縮小する。
- 既存実装がライブカメラ読取なら、プレビュー・開始/停止・権限案内を整理する。
- 既存実装が撮影・画像選択方式なら、その方式に合った「撮影して読み取る」「写真を選択」などの文言を使う。画像に合わせるためだけにライブスキャンを新設しない。
- 手入力の車体番号検索は在庫一覧の既存検索へつなげられる導線として提供する。
- 読取中、該当車両あり、該当なし、読取失敗、カメラ利用不可を区別して表示。該当なしと通信エラーを同じ文言にしない。
- サイドバーを含む共通スタイルは他画面と同一にする。画像の濃いサイドバーは採用しない。
- 生成画像内のQRは参考表現であり、アプリ内の有効なコードとして使わない。

参考画像: ![QRスキャン案](images/06-qr-scanner.png)

### 4.7 出荷予定

- 既存の「当日の出荷予定」を起点に、日付、台数、車両一覧を表示する。
- 列は車両、車体番号、保管場所、輸出先、書類、操作を基本とする。
- 「詳細」「出荷完了」を明示。既存の出荷完了処理と確認フローを維持する。
- 保管場所から対象区画のマップへつなぐ。
- 0台の場合は「本日の出荷予定はありません」。
- 画像の前日・翌日・日付選択は、既存の対応がない場合は実装対象外。
- 「在庫から出荷済みに移動します」という画像内説明は、既存処理を確認して事実に合う場合のみ使う。履歴や移動処理を新設しない。

参考画像: ![出荷予定案](images/07-outbound.png)

## 5. レスポンシブと状態表示

- PC: 1280×800、1440×900で主要導線が隠れない。ページ全体の不要な横スクロールをなくす。
- タブレット: 768px幅付近ではサイドバーを折りたたみ、本文を確保する。
- スマホ: 390×844、375×667で確認。サイドバーはメニューへ、フォームは1列、詳細は縦積み。
- モバイル在庫一覧は車名・車体番号・区画・状態・詳細を優先したカードまたは簡略表にする。操作のために毎回横スクロールする構成を避ける。
- マップは2次元なので必要な場合はマップ領域だけスクロールを許可。ページ全体を横にはみ出させない。選択車両情報は下部に表示する。
- 読込中は既存の読み込み状態を明示。空データ・検索結果0件・処理エラーは別の表示にする。
- フォーカス表示を設ける。アイコンのみのボタンに名前を付ける。入力ラベルを関連付け、クリック可能なdivを適切なbutton等へ整理する。

## 6. 添付画像と文章の優先順位

画像は生成されたデザイン参考案。実データの値、既存機能、必須項目、API仕様を保証しない。

| 画像との差異 | 実装時の扱い |
|---|---|
| 文字のみのロゴ | 現在の既存ロゴへ置き換える |
| QR画面の濃紺サイドバー | 全画面で白へ統一 |
| 登録画面の保管場所の重複 | 上部の1か所へ集約 |
| 日付・ナンバー・会社などの不一致 | 実データを使用する |
| 架空のユーザー名・通知・ヤード切替 | 既存機能がなければ表示しない |
| 車両写真・ソート・ページ切替・編集・日付切替 | 既存機能がなければ追加しない |
| QR見本や説明文 | 既存の実コードと処理に合う説明を使う |
| 「車体番号」「車台番号」等の揺れ | UIでは「車体番号」に統一、保存値・識別子は維持 |
| 書類準備済み / 準備完了等の揺れ | 本書の表示ラベルへ統一 |

## 7. 実装手順

1. AGENTS.md等のリポジトリ指示、使用技術、既存画面、ロゴの場所、状態管理、データ保存・API、利用可能なコンポーネントを確認する。
2. 現状と本書の差分を整理し、実装対象外の追加機能を切り離す。
3. 共通トークン、文字、サイドバー、ヘッダー、ボタン・入力欄を整える。
